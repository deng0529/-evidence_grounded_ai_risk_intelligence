# M4.2a-0 financial source scope handoff

This step preserves source scope for deterministic PDF observations. It adds no
M4 validation rules, reliability calculation, schema migration or cloud job.
The frozen M4 design remains authoritative.

## Root cause and schema decision

`pdf-table-v3` retained an explicit Group dimension but represented both Company
and unqualified balance-sheet headings with empty dimensions. Source evidence
retained only the amount/row locator. Admission and canonical concepts cannot
recover the missing distinction.

No schema extension is required. The existing immutable `evidence_reference`
PDF locator already has a `section` field for statement context, together with
page, row label, document and source links. `financial_source_fact` already
retains `evidence_id`, `parser_version` and dimensions. These are sufficient;
classification does not need another stored copy of the heading or evidence.

## Exact structured representation

- `SourceFinancialFact.statement_context`: optional text containing source
  statement headings, in layout order, separated by newlines when competing
  headings are present. Word text/case is retained; layout words are joined with
  spaces. For table extraction only headings preceding the year columns qualify.
- SQL storage: `evidence_reference.section` for the existing `evidence_id`.
  The existing `page` plus heading quote locate the supporting statement;
  `label` and `evidence_text` still locate the financial row and raw amount.
- `AccountsRepository.get_source` joins the existing evidence row to restore
  `statement_context` using SQL only. Publication rejects context/page disagreement
  between source observation and evidence locator. No R2 reader is involved.
- `SourceFinancialFact.source_scope`: a deterministic typed projection returning
  `COMPANY`, `GROUP` or `UNRESOLVED`. It is calculated from the retained structured
  context, not stored redundantly in a new SQL column.
- `pdf-heading-scope-v1` is pinned to `pdf-table-v4` and
  `financial-statement-structure-v4`. Both parser versions are stored on source
  facts and participate in their identities and processing fingerprints.
  Changing classification semantics requires a new parser/rule version.

One explicit Company balance-sheet/statement-of-financial-position heading gives
COMPANY. One explicit Group or Consolidated equivalent gives GROUP. Supported
headings may include an `as at ...` suffix. An unqualified heading, absent
heading, unsupported parser version or multiple competing headings remains
UNRESOLVED. A contradictory retained Group dimension also prevents COMPANY.
The classifier does not accept admission status, entity number or canonical
concept as evidence of scope.

Legacy `pdf-table-v3` explicit `pdf:entity-scope=GROUP` remains GROUP. Empty legacy
dimensions remain UNRESOLVED; no historical Company meaning is fabricated.

The structural parser records the context on the component's own page instead
of copying a possibly unrelated anchor's heading. Unqualified debt-note context
may therefore remain unresolved; no new scope recognition for arbitrary notes
or column layouts is introduced here. Existing Group rejection, numerical
extraction, direct concept mappings and financial admission behavior are unchanged.
Successful M3 publication of an unresolved-scope observation is not M4 admission.

## Historical recovery boundary

Inspection of the existing publication code/schema shows that old deterministic
row evidence generally lacks the heading. M4.0a semantic support can supply
explicit statement context for its linked semantic interpretations, but is not
a general source of headings for deterministic observations. A raw artifact
reference alone is insufficient. No live inventory was run in this step, so
the number/IDs of live records requiring recovery is not established.

Old observations and evidence remain immutable and readable. Exact retries of
new observations are idempotent. Versioned reprocessing uses the existing M3
append-only source/evidence/canonical publication mechanism: v4 identities are
distinct from v3 identities, and old rows are not updated. No automatic historical
backfill or new cloud command is enabled by this change.

For a separately reviewed historical recovery, the required bounded procedure is:

1. Select explicit document/source-observation IDs, company and processing-run
   scope. First inventory their SQL evidence sections, parser versions and any
   linked semantic support; do not infer Company from empty dimensions.
2. Where SQL lacks heading context, obtain separate authorization to read the
   selected documents' existing checksum-verified PDF/layout artifacts from R2.
   Prefer retained layout; no OpenAI or fresh document retrieval is required.
   Missing layout requires separately reviewed deterministic PDF/OCR recovery.
3. Reparse only those reviewed documents with the new versions, verify the
   old/new numeric values, concepts and row/period linkage, then publish new
   versioned observations through the existing transactional M3 path. Stop on
   ambiguity or unexpected financial changes; do not rewrite old identities.
4. Preserve processing lineage and review any duplicate observation selection
   separately. This handoff does not implement supersession/conflict rules.

Thus the forward Turso-only handoff gap is removed; old missing scope is still
unresolved until explicit source evidence is recovered under separate approval.
No historical live record is claimed to have been repaired or reviewed here.
