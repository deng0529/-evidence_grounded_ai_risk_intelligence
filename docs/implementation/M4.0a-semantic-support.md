# M4.0a semantic support handoff

This bounded handoff extension precedes M4.1. It implements no validation,
reliability, risk or ER policy. The authoritative M4 design remains
`docs/design-docs/m4-validation-evidence-reliability.md`.

Migration 006 adds `financial_semantic_support`: `interpretation_id` is the
primary/foreign key to `financial_interpretation`; `schema_version` is fixed to
`financial-semantic-support-v1`; `rationale` is nonblank TEXT; `context_json`
is validated JSON containing the existing FinancialContext source fact ID,
statement, section, supporting text and compatible concepts. Repository decoding
validates the typed schema. SQL triggers prohibit updates/deletes and restrict
inserts to accepted LLM_SEMANTIC interpretations. Repository checks enforce
source/document/target agreement. Migrations 001–005 are unchanged.

Future accepted semantic decisions publish support in the same transaction as
the interpretation and canonical publication. Missing or ambiguous context fails
publication. Rejected interpretations and accepted derivation plans retain their
existing behavior. Existing cached canonical outputs are not rewritten; use the
explicit historical backfill for old interpretations lacking support.

`AccountsRepository.get_semantic_support(interpretation_id)` performs SQL-only
retrieval, returning None when support is absent. Normal M4 must not fetch R2 to
fill that absence.

## Historical backfill, separately authorized

The command reads configuration from environment variables, not from `.env`.
Use the existing secure environment-loading workflow; never print credentials.
Metadata-only inventory (no migrations, writes or R2 reads):

```powershell
.\.venv\Scripts\python.exe examples/backfill_semantic_support.py --company <COMPANY_NUMBER>
```

After review, migration 006 must be separately approved and applied through the
existing migration runner. The command deliberately does not apply migrations.
Then select 1–100 explicit interpretation IDs:

```powershell
.\.venv\Scripts\python.exe examples/backfill_semantic_support.py --company <COMPANY_NUMBER> --apply --interpretation-id <REVIEWED_ID>
```

Repeat `--interpretation-id` for further reviewed IDs. This path reads existing
R2 interpretation artifacts through EvidencePersistence checksum verification,
checks processing/document linkage, schema-validates payloads, matches the
historical decision hash and immutable ledger, and checks the accepted value.
It appends support only; no extraction, normalization, OpenAI calls or R2 writes.
Existing canonical values and interpretation records remain unchanged.

Results are INSERTED, UNCHANGED or NOT_BACKFILLABLE. Missing/ambiguous context or
unsupported payloads are not fabricated. Infrastructure/checksum/immutable
conflicts fail explicitly. Each item is atomic; earlier successful items remain
if a later item fails. Exact retries are idempotent and still verify the artifact.
Inventory counts accepted semantic interpretations, not guaranteed backfillable
or missing-support records; those distinctions require further inspection.

Tests use synthetic local artifacts with network prohibited. They do not apply
cloud migrations or run live backfill. Production deployment and historical
backfill require separate human review and authorization.
